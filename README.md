# 选品有据 · Purchase Review

把“这个产品该不该采购”拆成有证据、可计算、可复核的判断，并分别输出内部评审与供应商反馈。

项目包含两个可独立使用的部分：**采购演示前端**和**通用采购评估 Skill**。前端用于互动演示，Skill用于让支持技能的智能体按真实资料执行跨品类采购评估，目前二者尚未通过后端连接。

## 项目功能

- 区分商品事实、供应商声明与未知信息，保留来源及待核验项。
- 结合新品收益、旧品替代、库存与资金占用讨论采购条件。
- 根据采购用途选择模型：转售看组合贡献，原料看合格产出成本，设备/软件看全生命周期成本。
- 内部评审和供应商沟通分开生成，对外文件不带内部经营数据。

## Navigation 与报告下载

顶部常驻导航提供三个视图，滚动后仍可直接点击：

| 视图 | 功能 |
| --- | --- |
| 采购评审 | 商品切换、产品资料、证据状态、SKU对比、成本与销量参数、三情景测算 |
| 内部评审 | 当前商品和参数的完整报告：贡献利润、资金需求、盈亏平衡、库存及补件要求 |
| 供应商视角 | 商品标识、补件、样品、交付及沟通要求，不包含内部测算 |

- 报告顶部点击 **下载 HTML**，获得可独立打开的静态文件。
- 点击 **打印 / 保存 PDF**，在浏览器打印窗口选择“另存为 PDF”。只打印当前受众的报告，使用A4分页样式；不是服务器直接生成PDF。
- 切换商品后报告同步更新；返回采购评审调整参数，再切回来即可看到最新结果。
- `#review`、`#internal`、`#supplier` 可直接进入对应视图。商品和参数保留在当前页面，刷新后恢复默认。
- 桌面、平板、手机均使用自然页面滚动，报告不再放在嵌套滚动弹窗内。

## 本地运行

完整本地演示包解压后双击 `index.html`，Windows也可双击 `打开演示.cmd`。无需安装网页依赖，建议使用Chrome或Edge。

可选本地HTTP服务：

```powershell
python server.py
# 浏览器访问 http://127.0.0.1:8150
```

公开仓库仅包含源码、模拟数据、说明和Skill。用户图片、品牌册PDF和提取图片保留在本地，`assets/` 已被Git忽略。新克隆缺少素材时仍可操作推演，图片区域会提示缺失。

如持有本次示例原始文件，可本地导入：

```powershell
python -m pip install pymupdf
python prepare_assets.py --bkt-image "你的产品图.jpg" --warmies-pdf "WARMIES BRAND BOOK 2024-2025.pdf"
```

这个脚本只适用于本次品牌册第22、30页的版式，不是通用文件解析器。产品素材权利属于相应权利人，仓库不分发附件。

## 示例与数据边界

前端使用BKT护腰坐姿椅、Warmies长毛绒企鹅（品牌册第22页）、小型蓝色龙（第30页）。Warmies名称按造型识别，正式型号待确认。

产品资料来自附件；采购价格、销量、库存、替代率及利润均为明确标注的模拟假设。品牌宣传中的授权、认证和性能未独立核验。“假设必要资料已通过”只是演示开关，不改变真实资料状态。

目前未接入实时AI、联网搜索、ERP、通用商品上传解析、数据库、账号权限或自动发信。源码推送不等于公网部署。整个演示网页含模拟内部数据，对供应商应只分享独立导出的供应商报告。

## 独立通用 Skill

入口：[skills/purchase-review/SKILL.md](skills/purchase-review/SKILL.md)。整个 `purchase-review` 文件夹可以单独复制使用，不依赖前端、三个商品或原始附件。

### 安装与调用

- Codex：复制到 `$CODEX_HOME/skills/purchase-review`（默认 `~/.codex/skills/purchase-review`），重新加载技能后调用 `$purchase-review`。
- OpenClaw：放入所用工作区的 `skills/`，按已安装版本刷新/检查技能。仍需在宿主配置模型、检索、文件读取及脚本执行能力。
- 其他兼容SKILL.md的智能体：加载该文件夹；不支持自动发现时，明确要求读取SKILL.md并执行。

调用示例：

> 使用 $purchase-review 评估这款准备采购的产品。市场是中国，采购用途是转售。附件为供应商资料，经营表为内部数据。请核验来源、比较现有SKU，给出条件式建议，分别生成内部报告和可发给供应商的反馈。

同样可评估耗材、食品、工业原料、设备、软件等：先识别用途，再补充该品类需要的信息与验收要求。跨品类适用的是评估流程，不同品类的成本模型、现行要求和专业验收不能一概而论。

### 输入与交付

输入：用途/市场/周期/币种、具体产品或版本、供应商报价及条款、买方需求和现有方案；有条件时提供真实库存/销售/使用数据。资料不足时输出初筛和补件，不编造收益。

输出：证据台账、条件式结论、可复核计算、内部报告和独立供应商反馈。对外只使用白名单字段，不含内部成本、库存、竞争报价、底价或退出名单。

标准库计算脚本支持转售组合贡献和不折现TCO：

```powershell
python skills/purchase-review/scripts/calculate.py input.json --output calculation.json
```

输入例子见 [数据合同](skills/purchase-review/references/data-contract.md)。原料良率等模型需按真实单位另建；脚本不预测需求、不核实认证、不自动批准采购。
